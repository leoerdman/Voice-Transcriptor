## 1. Сделано в 1.6.38 (дочинка двух пунктов «Открыто» из 11-23c)

- **A1. Правило покрытия больше не принимает соседнее слово за написание этого** (`covering_word`, `backend/remote_deepgram_live.py`). Каждое interim-слово помнит соседей своей гипотезы (`with_neighbours`). Позднее слово, совпадающее с соседом, никогда не «написание» этого слова (принцип «у него свой двойник» из `deepgram_dual._pairs`); если сосед ещё и перекрывает сильнее всех — решает порядок слов (как выравнивание в `deepgram_recovery`). Новая строка лога `N uncovered interim word(s) had no room beside the finals` — потеря места больше не невидима. Тест на реальных сообщениях: `backend/tests/test_covering_word_neighbours.py` (23-49-57 «text lab», 173438 «песню в»).
- **A1b. Пустой `punctuated_word` = токен, поглощённый форматированием** (`backend/deepgram_words.py`, общий для live и REST). Было «все все-таки» (145412): smart_format отдаёт `word="все", punctuated_word=""` + `word="-таки", punctuated_word="все-таки"`.
- **A2. Имя в начале вставленного куска сохраняет заглавную, если так записано в keyterms, уходящих в Deepgram** (`word_case.lexical_names`, `capital_is_lexical(..., names)`). Словарь — ровно `DeepgramLiveConfig.keyterms` (настройки + автотермины, `configured_keyterms`), без второго источника правды; доходит через `merge_readings(keyterms=)`, `splice_words_into_segments(keyterms=)`, recovery. Только сохраняет заглавную, никогда не добавляет; строчное написание той же формы в другом чтении снимает её; формы — ключом `auto_keyterms.term_key`. Пример: 052024 «свой claude Code» → «свой Claude Code».
- Стенд (17 записей, сырые сообщения, keyterms приложения) против 1.6.37: 2 лучше («Lab», «Claude»), 15 без изменений, хуже — нет; «он не должен», «деплой», «потерял», «слушаю/слушай» на месте. Бэкенд 1297 OK, desktop 701 OK.

### P2-1. Распознавание: «map map» вместо «разделялось»
- **Где:** запись `20261123-191519`, 12.7–13.7 с.
- **Статус:** ждёт A/B-прогона владельца.
- **Что видно:**
  - в последней гипотезе ru стоит «Jarvis map map map map map» (keyterms приложения, 68 штук);
  - финал обрывается на «оно»;
  - REST и прогон без keyterms слышат «разделялось».
- **Данные автословаря 1.6.38:** `configured_keyterms` из локальных `config.json` и `auto_keyterms.json` даёт ровно 68 терминов: 16 ручных + 52 автоматических (совпало с числом в дампе). `map`/`MAP`/«мэп» в словаре нет. Автоматические кандидаты по звучанию: `MCP` (92 записи, 156 употреблений) и `Mac` (32 записи, 45 употреблений); ручной `MacBook` тоже созвучен частично. Эти данные не устанавливают, какой термин вызвал «map».
- **Короткие латинские термины в фактически отправленном автословаре (ASCII-буквы, длина ≤ порога):** ≤2 — 3 (`AI`, `UI`, `ID`); ≤3 — 13 (`MCP`, `AI`, `API`, `Mac`, `Leo`, `UI`, `ID`, `CLI`, `GPT`, `Vox`, `Hub`, `LLM`, `ENV`); ≤4 — 16 (добавляются `HTML`, `Blur`, `Luna`). В ручном списке ещё 2 термина под порогом ≤4 (`Opus`, `SSOT`); автоматический фильтр ручные термины не затронет. В текущем автословаре также остаются нужные `Ultra` (66 записей, 125 употреблений в кэше) и `Транскриптор` (15 записей, 19 употреблений); ручной `Transcriptor` тоже отправляется.
- **Решение по защите:** правило отбора не вводить без сравнительного прогона. Порог ≤2 не затрагивает основной подозреваемый `MCP`; порог ≤3 удалит 13 действующих терминов, включая полезные аббревиатуры, и по данным словаря не доказано, что это улучшит распознавание. Ни фикстура, ни частоты автословаря не устанавливают причинность.
- **Что сделать.**
  1. **Владелец:** снять один и тот же `deepgram_live_ab` для записи `20261123-191519` с исходными 68 keyterms и с `keyterms=[]`, сохранив одинаковые язык/hints ru,en и остальные параметры; сравнить ru-гипотезу на 12.7–13.7 с.
  2. По паре прогонов подтвердить или отвергнуть влияние `MCP`/`Mac`/`MacBook`; менять правило автословаря только при воспроизводимом улучшении без неприемлемой потери терминов.
- **Где лежат данные:** сырые сообщения в scratchpad сессии (может быть очищен), фикстура — `backend/tests/fixtures/deepgram_live_20261123_191519.json`.
